# M7 国际物流跟踪（报价单维度）实施计划

## Summary

客户走柜（成交发货）后，运营端在订单详情页维护国际物流信息（船名/航次/提单号/柜号/起运港/目的港/ETD/ETA），并逐步追加物流节点事件（订舱→装柜→报关→开船→海运→到港→清关→签收）；客户端在报价详情页看到完整的动态时间线，订单列表卡片显示当前物流阶段与预计到港时间。

**已与用户确认的决策**：
- 录入方式：运营手动录入（不对接第三方追踪 API）
- 展示粒度：动态时间线节点（完整轨迹）
- 数据维度：挂在报价单上（1:1，嵌套存储，不建独立装运实体）

## Proposed Changes

### 1. 数据模型 — `apps/api/src/common/mock-db.ts`

`QuoteOrderRow` 新增可选嵌套字段（JSON 存储零迁移）：

```ts
export interface ShipmentEventRow {
  id: string;
  stage: 'booked' | 'loaded' | 'customs_cn' | 'departed' | 'on_water' | 'arrived'
       | 'customs_br' | 'duty_paid' | 'cleared' | 'delivered';
  note?: string | null;
  happened_at: string;  // 节点发生时间，默认录入时间
  created_by: string;
  created_at: string;
}

export interface ShipmentInfo {
  vessel?: string | null;        // 船名
  voyage?: string | null;        // 航次
  bill_no?: string | null;       // 提单号
  container_no?: string | null;  // 柜号
  pol?: string | null;           // 起运港
  pod?: string | null;           // 目的港（巴西）
  etd?: string | null;           // 预计开船日
  eta?: string | null;           // 预计到港日
  remark?: string | null;
  events: ShipmentEventRow[];    // 按 happened_at 正序
  updated_by?: string;
  updated_at?: string;
}
```

STAGE 中文映射（前后端共用文案，前端各自维护），清关环节细化为三个节点（已按用户确认）：
- booked 已订舱 / loaded 已装柜 / customs_cn 中国报关 / departed 已开船 / on_water 海运途中 / arrived 已到港
- **customs_br 巴西清关中 / duty_paid 关税已缴 / cleared 清关放行**（细化清关节点）
- delivered 已签收

### 2. 运营端 API — `apps/api/src/order/ops-order.controller.ts`

三个新接口均 `@Roles('operator', 'admin')`，前置校验订单存在且 `status==='done'`（不强制 deal_status=won，避免流程摩擦）：

1. `PUT /api/ops/orders/:id/shipment` — 保存基本信息。body 各字段可选，普通字段 ≤100 字符、备注 ≤500；首次调用创建 `{ events: [] }` 骨架；整体 merge 写回。审计 `action='order.shipment'`
2. `POST /api/ops/orders/:id/shipment/events` — 添加节点 `{ stage, note?, happened_at? }`，校验 stage 枚举；无 shipment 时自动创建骨架。审计 `action='order.shipment.event'`
3. `DELETE /api/ops/orders/:id/shipment/events/:eventId` — 删除误录节点。审计 `action='order.shipment.event_del'`

现有接口扩展：
- `GET /api/ops/orders` 列表追加 `shipment_stage`（最新节点的 stage，无则 null）与 `shipment_eta`
- `GET /api/ops/orders/:id` detail 返回完整 `shipment`

### 3. 客户端 API — `apps/api/src/order/client-order.controller.ts`

- `GET /api/client/orders/:id` detail 返回完整 `shipment`（events 已按时间正序）

## Assumptions & Decisions

- 物流录入条件：订单 `status==='done'` 即可（不强制成交标记 won）
- `shipment` 更新会经 `QuotesRepo.update` 刷新订单 `updated_at`——客户端"最近发布/更新"时间随之推高，属合理动态语义
- sales 角色进不了订单详情页（现有权限不变），但列表可见 `shipment_stage` 摘要
- 部署切 TypeORM/PostgreSQL 时 `shipment` 作为 JSON 列存储（延续现有 MockDB→PG 切换约定）
- 用户自行加的行级截图关联（row_no/row_map/shotsByRow 等）与 Deals.tsx、styles.css 近期改动一律不动
